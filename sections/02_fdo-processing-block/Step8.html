[S-8]: FDO Attributes Validation

The step requires that successfully validated one or more profiles resulting in one or more sets of attributes. For each attribute, this step determines if the attribute's value is appropriate given its attribute definition. The validation process will greatly vary in complexity depending on the rules of the specific attribute definition.
Inputs
The inputs consist of the list of Validated_Profile (especially Valid_Attributes and Invalid_Attributes) from . Even if the cardinality of attributes was not valid (Invalid_Attributes), a validation of the attribute's value against its attribute definition may still be performed. Note that this step could be used with any attribute list that would need validation.
Outputs
The output will be a list of Validated_Attribute where each attribute will have a Validity_Status and a Error_Description.
Expected behavior
The FDO attribute processing iterates over the list of attributes using the following steps:
  1. This step checks whether the attribute definition specifies any validation rules. If it does, it applies the rules on the attribute’s value. It will set the Validity_Status and any Error_Description it may have generated. The Validity_Status will include, but is not limited to, the following list:
    • VALID: Indicates that the value is appropriate according to the validation rules.
    • PARTIALLY_VALID: Indicates that the value is partially valid. An example is the case of a 0.FDO/DateTime attribute, where the date is filled in but there is no time information. While incomplete, this value could still be of interest to the client.
    • INVALID: Indicates that the value did not comply with the validation rules.
